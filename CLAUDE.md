## Стек и запуск

- **Astro + Tailwind v4** (токены через `@theme`).
- **Порт зафиксирован: 4330** (`strictPort` в `astro.config.mjs`). Локальный адрес
  `http://localhost:4330` не должен «уезжать» — при занятом порте сборка падает явно.
- Когда пользователь пишет **«открою локально» / «запусти»** → сразу `npm run dev`
  (запускать в фоне, отдать ссылку `http://localhost:4330`).
- Скрипты: `npm run dev` | `npm run build` | `npm run preview`.

## Производительность (правила зафиксированы)

- **Все фото — только WebP** (`public/images/**/*.webp`). Новые PNG класть в
  `public/images/` и прогонять `node scripts/convert-images.mjs` (sharp, q80;
  полноэкранные clinic/* ужимаются до 1600px; PNG-оригиналы уезжают в
  `assets-src/originals-png/`, в dist не попадают).
- **`.blob` — radial-маска, НЕ `filter: blur(80px)`** (в `global.css`) — визуально то же
  пятно, но без дорогой GPU-растеризации. Blur-фильтры на блобы не возвращать.
- **`backdrop-filter` — только на крупных `.glass`-плашках.** Мелкие чипы/теги/подписи —
  просто `--veil`/`--veil-strong` без blur.
- **Автоплей (hero-слайдер, слайдер стационара, прейскурант-тикер) ходит только когда
  блок на экране** — хелпер `autoplayIO` в скрипте index; тикер запускается классом
  `.run` (по умолчанию `animation-play-state: paused`).
- Секции `.sec` — `content-visibility: auto` (в `global.css`); первый hero-кадр —
  `fetchpriority="high"`, остальные `<img>` — `loading="lazy" decoding="async"` + width/height.

## Тексты страниц для сверки с клиникой (правило зафиксировано)

Контент лечебный, каждый пункт выверяется клиникой — поэтому весь видимый текст
каждой страницы дублируется текстовой выгрузкой в `docs/тексты-страниц/*.md`
(файл на страницу; клиент правит их копию в Google Doc, правки возвращаются в код).

- Генерация: **`npm run texts`** (= `astro build` + `scripts/extract-page-texts.mjs`);
  текст берётся из собранного `dist/`, то есть дословно совпадает с сайтом.
- **Правило: сверстал новую вкладку или изменил текст существующей → сразу перегенерировать
  выгрузку `npm run texts` и закоммитить вместе с правкой.** Выгрузка не должна отставать от кода.
- Главная — исключение: её текст ведётся вручную в `docs/тексты-главной.md`
  (там же сквозные шапка и футер — из повкладочных файлов они опущены); `/tokens` не выгружается.
- Файлы выгрузки руками НЕ редактировать — источник правды по тексту всегда код страниц.
- Формат пометок в выгрузке: `<mark>` сохраняется тегом; `*(кнопка)*`, `*(поле: …)*`,
  `*(секция: id)*`, `*(хлебные крошки)*` — служебный курсив, по `*(секция: id)*` правки
  клиента находят место в коде.

### Заливка в Google Docs

Клиентская копия готовится режимом `node scripts/extract-page-texts.mjs --gdoc <каталог>`:
рядом с `NN.md` кладётся `NN.html` и `manifest.json` с названиями документов. Каталог
временный, в git не хранится.

- **Заливать в Google Drive нужно именно HTML** (`contentMimeType: text/html`). Markdown
  Drive тоже принимает, но выбрасывает `<mark>` — заливка маркера теряется. Через HTML
  доезжает всё: заливка маркера, таблицы, заголовки, служебный курсив пометок.
- **После заливки — обязательная сверка** `node scripts/verify-gdoc.mjs <каталог> NN <файл>`,
  где файл — текст, вычитанный обратно из созданного документа. Скрипт ищет каждый фрагмент
  выгрузки в документе и печатает пропажи. Ноль пропаж = документ совпал дословно.
  Проверка не формальность: заливка идёт текстом и **рвётся на середине незаметно** —
  документ выглядит целым, а половины страницы нет.

### Новая страница: сначала текст, потом вёрстка

Для НОВОЙ страницы обычный путь (код → `dist` → выгрузка → документ) недоступен — страницы
ещё нет. Порядок обратный, и он дешевле: текст пишется сразу в формате выгрузки, клиника
его вычитывает, и только утверждённый текст уходит в вёрстку.

- Черновики — `NN.md` в том же формате, что выгрузка (преамбула, `*(секция: id)*`, `<mark>`).
  `node scripts/draft-to-gdoc.mjs <каталог>` кладёт рядом `NN.html` для заливки.
- Голос и требования к тексту — навык **`medical-copy`** (объяснение терминов, запрет
  обещаний и выдуманных данных клиники, ФЗ-38, структура страницы).
- **Пока страницы нет — источник правды документ. Как только страница свёрстана — источник
  правды снова код**, а документ обновляется из него обычным `npm run texts`.
- После вёрстки совпадение страницы с утверждённым текстом проверяется машинно:
  `diff-gdoc.mjs` против того же документа. Пустой отчёт = свёрстано ровно то, что утвердили.

### Правки клиента обратно в код

`node scripts/diff-gdoc.mjs <каталог --gdoc> <каталог с вычитками>` — что клиент поменял
в документах, списком с привязкой к месту в вёрстке. Вычитки складываются файлами `NN.txt`.

- Сравнение **двустороннее**: клиент правит документ как ему удобно и не обязан укладываться
  в нашу структуру — может переписать фразу, дописать абзац от себя или снести блок целиком.
  Удаления в отчёте видны наравне с добавлениями, поэтому `verify-gdoc.mjs` (он смотрит
  в одну сторону) для этой задачи не годится.
- Привязка: `*(секция: id)*`, а где секция без id — ближайший заголовок выше. Метки секций
  есть только на 6 страницах из 14; на остальных ориентир по заголовку.
- Разметку Google (`**` у заголовков, экранированные скобки, выброшенные `---`, склеенные
  переносы в списках) нормализация гасит — на неправленых документах отчёт пустой.
- **Обратно в Google Docs заливать после каждой правки не нужно**: правка клиента уже в его
  документе. Перезаливать имеет смысл, только когда текст поменяли МЫ (новая вкладка,
  наша редактура) и копия клиента устарела.

## Дизайн-направление (синтез двух референсов)

База — **Geniestudio** (воздушный дневной свет), дисциплина hairline-бордеров — **Awesomic**.
Из Genie выкинуты игрушечные 3D-рендеры; из Awesomic выкинуты zinc-серость и оранжевый акцент.

Формула: **светлое воздушное полотно → размытые пастельные градиент-блобы на фоне →
поверх стеклянные плашки (backdrop-blur) с тонким 1px бордером → крупные спокойные
заголовки среднего веса, tight tracking → один сдержанный синий акцент → тёмный
near-black CTA как единственный «плотный» элемент.**

### Палитра (обновлено — холодная «северная волна/лёд», БЕЗ розового)
- **Акцент = «северная волна» `#3a8ca6`** (холодный сине-бирюзовый) — ссылки, иконки,
  kicker, hover. Тёмный `#29697f` для текста/hover.
- **Вторичный = фиолетовый `#7c6cd6`** (+ сиреневый `#e9e2fb`, серо-синий `#6a7f99`).
- **Розовый УБРАН** — палитра прохладная, пастельная (лёд/голубой/сиреневый/серо-синий).
- **Кнопки — брендовые (не тёмные/чёрные!)**: `--cta-fill: var(--c-teal-deep)`. Тёмный
  charcoal больше НЕ используем.
- **Плашек РОВНО ДВА ВИДА: градиентная и чисто белая.** Градиентная — единый
  `linear-gradient(var(--ang), var(--g-uni-a), var(--g-uni-b) 55%, var(--g-uni-c))`, угол
  `--ang` у каждой свой. Белая — `#fff` + hairline. Третьего вида нет: ледяной однотон
  (`--tile-teal` как фон плашки), полупрозрачность и «стеклянность» под запретом.
  Логотип — фикс-SVG (teal+розовый).

### Do
- Холст `#ebf5ff`, **белая плашка — чисто белая `#fff`** (`--surface-card` = `--c-paper`,
  как и `.glass`) + hairline: глубину даёт голубой холст. Двух разных «белизн» рядом не
  держим — соседняя `#fafdff` читалась как «прозрачная плашка».
- **Плашки одного смысла в ряду выглядят ОДИНАКОВО** — одна и та же из двух разрешённых
  заливок; смешивать белую и градиентную в одном ряду нельзя. Ни стеклянности, ни
  полупрозрачности, ни разной белизны. Hover карточки НЕ меняет саму плашку (ни рамку, ни
  фон, ни сдвиг) — красится только ссылка/заголовок внутри: иначе карточка под курсором
  читается как «другая плашка».
- Карточки ВНУТРИ градиентной плашки — чисто белые без обводки (градиент сам их отделяет).
- **Ни буллитов, ни разделительных линий.** Запрещены точки-маркеры (`::before` с кружком),
  `list-style`, цифры `::marker` — и hairline-линии между пунктами, рядами editorial-списков,
  вопросами FAQ, шагами плана. Перечисление держит **вертикальный ритм**: линий нет, поэтому
  и отступы между пунктами меньше (≈12–14px вместо 22px). Линии остаются только там, где
  они часть структуры: строки таблиц (прайс, таблица маркеров), граница липкой шапки,
  отбивка футера.
- **Иконок на информационных страницах нет.** Абстрактные декоративные пиктограммы
  (график, часы, лупа, «запрет», щит) запрещены — смысл несут заголовок и текст. Иконки
  остаются только функциональными: в кнопках, шапке/навигации, шевроны у чипов-ссылок.
- **Приём `<mark>` — наша изюминка и ЕДИНСТВЕННЫЙ способ выделить фразу** (жирность внутри
  текста запрещена, см. глобальный CLAUDE.md). Чёткий прямоугольник `--hl-fill` (цвет
  `::selection`), без скруглений. **Условие: фраза укладывается в ОДНУ строку** — подложка,
  разорванная переносами на три куска (особенно в лиде на градиенте), выглядит грязно;
  в таком месте не выделять вовсе или сократить фразу. Одна-две фразы на секцию, никогда
  не абзац целиком. Отдельный кейс — строка-итог «Результат» в «Как мы лечим»: короткая
  строка целиком под маркером.
- **Мера строки — токенами** `--measure-text/-lead/-head/-head-lg/-prose`,
  ширины плашек — `--tile-narrow/-mid/-prose` (`tokens.semantic.css`). Мера нужна только
  тому, что живёт на всю ширину страницы; внутри карточки/колонки её задаёт сам модуль.
- **FAQ — статичный список** (`Faq.astro`): вопрос-заголовок + ответ видны сразу, две
  равные колонки, левый край. Аккордеонов (`details`/`summary`, «+», JS-разворот) нет нигде.
- **Всё по левому краю.** `text-align: center` на заголовках, абзацах и колонках запрещён;
  исключение — нормативная плашка «Имеются противопоказания». Сузить плашку и отцентровать
  её как блок (`max-width` + `margin-inline: auto`) — можно и нужно.
- **Кнопки — ТОЛЬКО ЗАЛИВКА, обводок нет нигде** (единственный источник — `global.css`,
  в страницах не дублировать):
  - `.btn.btn-dark` — основная, бирюза `--cta-fill`;
  - `.btn.btn-light` — вторичная на холсте, фото и градиенте: сплошной белый `--btn2-fill`
    (стеклянных/ghost-кнопок с обводкой больше нет, `.btn-ghost`/`.btn-ghost-dark` —
    псевдонимы `.btn-light`);
  - `.btn.btn-ice` — вторичная **на белой плашке**: ледяная заливка `--btn3-fill`
    (белая на белом не читается).
  - **На hover кнопка только КРАСИТСЯ** — никаких `transform: translateY`, подпрыгиваний
    и сдвигов.
- **Чипы — наоборот, контурные:** `.link-chip` и родня (фильтры врачей, метки, кнопка «Аа»,
  номера-кружки) — hairline-обводка без заливки, hover = перекраска обводки и текста,
  активное состояние = заливка `--cta-fill`. **Если чип — гиперссылка, у него обязательно
  наш шеврон `›`** (`.chev-r`).
- Hairline-обводка: на плашках/карточках, полях форм, таблицах и чипах — **не на кнопках**.
- Стекломорфизм `.glass` на размытых **цветных** кругах `.blob` (teal/pink/blue; мягкость —
  radial-маска, см. «Производительность»).
- Фото врачей — **во всю ширину плашки** (full-bleed), не мелкие аватары-кружки.
- **Кегль — ТОЛЬКО токеном шкалы, хардкод `font-size` запрещён.** Шкала — 10 ступеней +
  2 для крупных цифр (`tokens.base.css`): `--fs-caption` 13 · `--fs-body-sm` 15 ·
  `--fs-body` 16 · `--fs-body-lg` 18 · `--fs-sub` 20 · `--fs-h-sm` (h3 карточек, вопрос FAQ) ·
  `--fs-h` (h3 крупные, заголовки плашек) · `--fs-h-lg` (ВСЕ h2 секций) · `--fs-display`
  (h1 внутренних) · `--fs-hero` (h1 главной) · `--fs-num` / `--fs-num-lg` (номера, счётчики).
  Заголовочные ступени уже резиновые — свой `clamp()` в странице не писать. Нужен размер,
  которого нет → выбрана не та роль, а не «добавим ступень». (Было 45 уникальных кеглей:
  13/13.5, 14/14.5, 15/15.5, 16/16.5 неразличимы и только рассинхронизировали страницы.)
- Крупные заголовки, вес 600, letter-spacing ≈ −0.02em, line-height ≈ 1.1 (110%).
- **Наборный текст — чистый тёмный `#0a0d12`**, без серости и полупрозрачности
  (серый только для мелких служебных подписей: даты, метки).
- Тени заменяем **hairline-бордерами 1px**; максимум — мягкая тень для «поднятия» стекла.
- Тёмный CTA `#181d27` — плотный якорь действия.

### Don't
- **Капс запрещён нигде** (`text-transform: none`).
- Никаких кислотных/траурных оттенков; фирменные teal/розовый держим мягкими.
- Не более двух washi-пятен в одной секции.
- Не чистый чёрный `#000` — использовать `#0a0d12`.
- Не игрушечные 3D-иллюстрации; не мелкие круглые аватары врачей.
  Исключение (утверждено): плашки преимуществ — БЕЛЫЕ карточки (surface-card +
  hairline), внизу мягкие clay-рендеры в ледяной гамме на ЧИСТО БЕЛОМ фоне
  (`.adv-ill`, multiply; промпты в `docs/illustration-prompt-adv.md`). Людей в
  иллюстрациях НЕ рисовать (только предметы). «Прозрачные цены» — не картинка,
  а живой мини-прейскурант-тикер (`.adv-pricelist`, listается сам).

## Архитектура токенов (3 слоя)

```
src/styles/
  tokens.base.css       — СЛОЙ 1: примитивы (сырые значения; меняются между концепциями)
  tokens.semantic.css   — СЛОЙ 2: роли (bg-canvas, surface-card, text-strong…) + шрифт-пресеты
  tokens.theme-flat.css  — ТЕМА «flat»: переопределения токенов под :root[data-theme="flat"]
  tokens.theme-apple.css — ТЕМА «apple»: токены + scoped-блок компоновки (hero по центру)
  global.css            — СЛОЙ 3: @import tailwind + @theme (мост в утилиты) + база
  fonts.ts              — загрузка всех шрифтовых кандидатов (импортится в layout)
```
Компоненты используют только семантику / `@theme`-утилиты (`bg-canvas`, `text-ink`,
`border-hairline`, `font-display`, `rounded-card`, `.glass`, `.blob`). Тема =
переопределение токенов под `:root[data-theme="…"]`.

## Финал (зафиксирован — работаем ТОЛЬКО в этом дизайне)

Пользователь выбрал единственную концепцию: **тема «Воздух» + шрифт Lora**. Все остальные
темы (`flat`, `apple`) и шрифт-пресеты (`onest`, `playfair`, `grotesk`) — **удалены** из
проекта вместе с их файлами, атрибутами `data-theme`/`data-type`, панелью переключателей
и лишними пакетами шрифтов. Больше не добавлять — один дизайн.

- **Концепция «Воздух»:** голубой холст `#ebf5ff`, стекло (`.glass`, backdrop-blur), размытые
  пастельные блобы `.blob`, радиусы 16–28px, тёмный CTA `#181d27`.
- **Шрифты:** заголовки — **Lora** (засечка), наборный — **Manrope**. Приём `.i-serif`
  (`<em class="i-serif">слово</em>`) — акцентное слово заголовка засечкой Lora,
  **прямое начертание**. **Italic ЗАПРЕЩЁН нигде** (как и капс): глобально
  `em, i, cite, dfn, address { font-style: normal }` в `global.css`, `font-style: italic`
  не писать ни в токенах, ни в страницах.
- **Единый градиент (одна тональность, розовый/сиреневый из фонов исключены):**
  `--g-uni-a/-b/-c` (лёд → бирюза кнопки → голубой) — на всех цветных плашках, угол
  per-плашка через `--ang`; `--grad-uni` — тот же градиент как фон hero/секций.
  Старые `--grad-daylight`/`--grad-lilac` удалены.
- **Приём `<mark>`** — «маркер» внимания: чёткий прямоугольник `--hl-fill` под КОРОТКОЙ
  ключевой фразой (цвет = `::selection`), без скруглений, `box-decoration-break: clone`.
  Фраза должна укладываться в одну строку.
- **Каталог разделов** — «шахматка»: плашки 2/4/6 с фото (`public/images/catalog/*.webp`,
  промпты в `docs/photo-prompt-catalog.md`, точка кадрирования — `pos` → `--photo-pos`).

**Железное правило: никаких хардкодов в страницах** — всё на токенах:
- радиусы — `var(--r-pill|--r-card|--r-glass|--r-input|--r-sm)`, не `9999px`/`14px` руками;
- белые полупрозрачные заливки — `var(--veil)` / `var(--veil-strong)` + `blur(var(--veil-blur))`;
- фон шапки — `var(--head-fill)`; kicker на тёмном фото — `var(--accent-on-dark)`;
- цветные плашки — фон `--tile-*`, каталог — `--cat-*-bg/-ink/-orb1/-orb2`;
- градиенты-заглушки фото в данных страниц — только `var(--c-wash-*)`, не hex.
